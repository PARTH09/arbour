# Architecture

Arbour is a local-first mind-map editor that can grow into a multiplayer workspace without replacing the document model.

## Current repository

The repository started empty aside from git. Phase 1 adds:

- `apps/web` — Next.js 16.4.2, React 19, TypeScript, Tailwind CSS 4
- `packages/mindmap-core` — document model, commands, layout, validation, and tests
- `docs` — decisions for the phases that are not built yet

UI primitives follow the shadcn pattern: Radix primitives, Tailwind, and a small `cn` helper. They live in the app instead of being generated by the shadcn CLI.

## Why the document model is separate from the canvas

Every edit is a command that returns a new document. The canvas, the outline, export, and undo all read that document. A later server can store the same command stream. A later renderer can draw it without learning a second hierarchy.

Tree rules live in the command layer:

- The central topic cannot be deleted or reparented.
- A topic cannot be placed inside its own subtree.
- Deleting a topic deletes its subtree and the connectors that pointed at it.
- Every non-floating topic has exactly one tree connector from its parent.
- Cross-links are a second edge kind. They do not change the parent pointer.

Style precedence:

1. A document theme writes every topic that has not been formatted by hand.
2. A new child copies its parent's border color and font. Children of the central topic take the next branch color instead.
3. A manual edit sets `themeLock`, and later themes leave that topic alone.
4. A tree connector follows the child border color until someone sets the connector color.

## Canvas engine

Phase 1 uses `@xyflow/react` 12.12.0 for pan, zoom, selection, the minimap, and hit testing. Topic and connector drawing are custom. Layout is not React Flow's.

| Keep React Flow | Replace it later if needed |
| --- | --- |
| Viewport, wheel zoom, box selection, and the minimap are already solid. | Each topic is a DOM node. Large maps will spend their time in layout and paint of those nodes. |
| Custom nodes and edges were enough for mind-map curves, shapes, and editing. | The document model does not mention React Flow, so a canvas or SVG renderer can be swapped in. |
| Dragging uses local positions and commits once, on drop. | 5,000 DOM nodes were not profiled in the browser. The layout math for 5,000 topics is about 40 ms. |

A custom canvas from day one would have delayed keyboard editing and the inspector. It is the right follow-up only after a real map shows the DOM path is too slow.

## Persistence

Maps are written to `localStorage` after a short pause. The status is Saving, Saved locally, Saved on this device while the browser is offline, or Not saved. Mouse moves are not written. A drag commits when the pointer is released. Typing in one topic is one undo step.

Server persistence, in Phase 3, should keep this rule: small maps can be saved as a snapshot, and larger maps should append validated operations. The client must not show Saved until the server acknowledges the write.

## Repository shape

```
apps/web/src/features/editor   canvas, inspector, library
packages/mindmap-core/src      commands, layout, schema, templates
docs                           architecture, database, later phases
```

A FastAPI service can be added under `apps/api` when accounts exist. It should import the same document rules or a Python port of them, and it should not grow a second, divergent node model.

## Phases

1. **Editor, done in this tree.** Canvas, hierarchy, layout, shortcuts, undo, local library, import and export.
2. **Editing depth.** Richer branch styling, alignment while dragging tree topics, and browser tests for the shortcuts.
3. **Persistence.** Auth, Postgres, workspaces, folders, autosave against the API, and recovery.
4. **Production editor.** Permissions, comments, snapshots, PDF, uploads, and accessibility passes on the outline.
5. **Collaboration and AI.** Presence, a CRDT or operation log for concurrent edits, and generated maps that are previewed before they are inserted.

## Risks

- React Flow's DOM nodes are the likely ceiling, not the layout math. Measure a 1,000-topic map in the browser before optimizing.
- `localStorage` is capped around 5 MB and is not a backup.
- Undo stores full document snapshots, capped at 80. That is simple and correct for current maps, and too heavy if a snapshot is a multi-megabyte document.
- Concurrent edits are undefined. WebSockets alone will not resolve two people reparenting the same topic. That needs an explicit operation model, likely Yjs for text and server-checked structural operations.
- Layout runs on the client. The server should validate structure, not trust pixel positions.
- Image topics accept an http(s) URL only. There is no upload, and imported HTML is never executed.
